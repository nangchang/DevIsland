## 1. 비전

> **DevIsland는 AI 에이전트 시대의 관제탑(mission control)이다.**
> 개발자가 여러 AI 에이전트를 동시에 운용할 때 — 신뢰(승인 게이트), 인지(상태 모니터링), 흐름(컨텍스트 복귀)을 책임지는 가장 가볍고 방해 없는 macOS 네이티브 레이어.

### 환경 변화와 기회

AI 코딩 에이전트 사용 패턴은 빠르게 바뀌고 있다:

| 시기 | 패턴 | DevIsland의 역할 |
|---|---|---|
| 과거 | 터미널 1개, 에이전트 1개를 지켜보며 사용 | 승인 알림 + 포커스 복원 (현재 핵심 기능) |
| 현재 | 워크트리 N개에 에이전트 N개를 병렬 운용 | 세션 추적·서브에이전트 그룹화 (부분 지원) |
| 다가옴 | 자리를 비운 사이에도 에이전트가 작업, 사람은 승인·방향만 결정 | **fleet 관제 + 원격 승인 + 정책 자동화** (미지원 — 기회) |

이 변화의 각 단계에서 사용자가 잃는 것은 **"지금 무슨 일이 벌어지고 있고, 어디에 내 결정이 필요한가"에 대한 감각**이다. DevIsland의 모든 기능은 이 감각을 되돌려주는 방향으로 수렴해야 한다.

### 제품 원칙 (기능 채택 기준)

새 기능 후보는 아래 5가지를 통과해야 한다. 하나라도 어기면 플러그인으로 밀어내거나 기각한다.

1. **비침습**: 사용자의 터미널·에디터 흐름을 빼앗지 않는다. 보조하고 비킨다.
2. **승인 신뢰**: 승인 게이트의 무결성을 해치는 편의 기능은 만들지 않는다. (예: "전부 자동 승인" 같은 전역 스위치는 시간·범위 제한 없이는 금지)
3. **1초 인지**: 노치를 흘긋 봤을 때 1초 안에 상태가 읽혀야 한다. 정보를 더할수록 요약 계층이 먼저다.
4. **로컬 우선**: 코어 기능은 네트워크 없이 동작한다. 외부 전송은 명시적 opt-in + 최소 데이터.
5. **코어는 얇게, 확장은 플러그인으로**: 모든 사용자에게 필요하지 않은 기능은 built-in 플러그인 또는 v2 외부 플러그인으로 만든다.

## 2. 기능 후보 전체 지도

지금까지의 검토에서 도출한 후보를 가치/노력으로 평가했다. (가치: 비전 적합도 × 사용자 빈도, 노력: 구현+유지보수)

| 기능 | 가치 | 노력 | 기존 기반 (이미 있는 것) | 배치 |
|---|---|---|---|---|
| 규칙 제안 (반복 승인 → 룰 승격 제안) | ★★★ | 낮음 | `approval_decisions` 테이블, deterministic rule ID | H1 |
| 브리지 헬스 진단 뷰 | ★★★ | 낮음 | replay log, 토큰/transport 상태 | H1 |
| macOS 알림 센터 연동 | ★★★ | 낮음 | `showNotification` capability 설계 존재 | H1 |
| 노치에서 프롬프트 회신 (PTY 주입 정식화) | ★★★ | 중간 | `devisland_pty.py` + `injection` 응답 필드 (실험 기능) | H1 |
| 노치에서 새 세션 시작 (Quick Launch) | ★★ | 낮음 | `TerminalFocuser.openNewWindow` 이미 구현됨 | H1 |
| 세션 인사이트 v1 (승인·세션 통계) | ★★ | 중간 | SQLite에 데이터 전부 축적 중, `approval.decided` 이벤트 설계 완료 | H1 |
| Fleet 보드 (멀티 세션 관제 뷰) | ★★★ | 중간 | SessionStore, 서브에이전트 그룹화, 세션 히스토리 창 | H2 |
| Git 컨텍스트 (브랜치·워크트리·PR 상태 표시) | ★★★ | 중간 | `workspaceRoot` 이미 전 세션에 전파됨 | H2 |
| 승인 정책 프로파일 (워크스페이스별/시간제한 자동 승인) | ★★★ | 중간 | `workspaceRoot` 스코프 룰, `ToolKnowledge` 위험도 | H2 |
| 외부 알림 채널 (Slack/Discord/webhook) | ★★ | 중간 | 플러그인 v2 `networkAccess` 설계 필요 | H2 |
| 비용·토큰 추적 | ★★ | 중간 | 훅 페이로드 파싱 확장 필요 (provider별 가용성 상이) | H2 |
| Provider SDK화 (신규 CLI 에이전트 어댑터) | ★★ | 중간 | `HookEventNormalizer`/`ProviderAdapter` 분리 구조 | H2 |
| 원격 승인 (모바일/웹 컴패니언) | ★★★ | **높음** | IPC 토큰·envelope 구조 (보안 선결 조건 있음) | H3 |
| 플러그인 v2 (외부 런타임·서명 배포) | ★★★ | 높음 | v1 완료, v2 설계 문서 존재 | H3 |
| 커뮤니티 에셋 생태계 (버디·사운드·플러그인 팩) | ★★ | 중간 | OpenPeon 팩 로더, 버디 시스템, v2 에셋 팩 설계 | H3 |
| 팀 정책 공유 (룰셋 export/import) | ★★ | 낮음~중간 | rules 테이블 → JSON 직렬화 | H3 |
| 음성 요약 (TTS 상태 브리핑) | ★ | 중간 | CESP 오디오 경로 | 보류 |
| 에이전트 자동 오케스트레이션 (큐·일괄 지시) | ★ | 높음 | — | 보류/안티골 경계 |

## 3. Horizon 1 — "지금 흐름을 완성한다" (v0.13~v0.15, ~3개월)

기술 로드맵의 v0.12 보안 하드닝 이후, 기존 데이터와 반쯤 구현된 기능을 사용자 가치로 전환하는 단계. 큰 신규 표면 없이 체감 가치를 올린다.

### H1-1. 규칙 제안 (Approval → Rule 승격)

같은 도구/명령 프리픽스를 N회(기본 3회) 수동 승인하면, 승인 UI에 "이 도구를 항상 허용할까요?" 제안 칩을 띄운다. 수락 시 기존 `persistApprovalScope` 경로로 룰 생성.

- 근거 데이터: `approval_decisions`에 source=user 기록이 이미 쌓인다.
- 효과: 승인 피로(이 앱의 핵심 적)를 데이터 기반으로 줄인다. 정책 기능의 사용률을 끌어올리는 진입로.
- 주의: 제안은 **once 승인 흐름을 늦추지 않는 위치**(결정 후 토스트)에 배치. 원칙 3.

### H1-2. 브리지 헬스 진단 뷰

설정 또는 메뉴바에 "진단" 패널: 훅 설치 상태(provider별 settings 파일 검사), 토큰 모드(정상/grace 경고), transport·포트, 최근 이벤트 수신 시각, 브리지 로그 tail.

- 효과: 현재 가장 흔한 지원 문제("훅이 안 와요")를 사용자가 자가 진단. 검토 보고서 S3(grace mode 경고)도 이 화면이 수용.

### H1-3. macOS 알림 센터 연동

노치를 못 보는 상황(전체화면 앱, 다른 데스크탑, 외장 모니터만 사용)을 위해 승인 요청·작업 완료를 `UNUserNotificationCenter`로도 발행(설정 opt-in). 알림의 Approve/Deny 액션 버튼으로 즉시 결정 가능하게.

- 효과: H3 원격 승인의 전 단계. "노치를 놓치면 끝"이라는 현재 한계를 해소.
- 주의: 노치 표시와 중복 발행하지 않도록 게이트 (이미 있는 `hasDetachedWindow` 억제 패턴 재사용).

### H1-4. 노치에서 프롬프트 회신 — PTY 주입 정식화

실험 기능인 PTY 래퍼(`ptyEnabled`)와 `injection` 응답 필드를 다듬어, idle 상태 세션에 노치에서 바로 다음 지시를 타이핑해 보낼 수 있게 한다. AskUserQuestion 구조화 응답이 이미 있으므로 UI 패턴 재사용.

- 선결: PTY 래퍼의 raw mode/SIGWINCH 개선 (검토 보고서 A4).
- 효과: "확인하러 터미널로 돌아간다"에서 "노치에서 끝낸다"로 — 제품의 인터랙션 상한을 올리는 기능.

### H1-5. Quick Launch

세션 히스토리/노치에서 "이 워크스페이스에서 새 세션 시작" 액션. `TerminalFocuser.openNewWindow(appName:command:)`가 이미 있으므로, 워크스페이스 루트 + 선호 터미널 + provider 선택만 UI로 연결하면 된다.

### H1-6. 세션 인사이트 v1 (built-in 플러그인)

플러그인 설계의 `approval.decided` 이벤트(설계 완료, 미구현)를 구현하고, 이를 소비하는 `InsightsPlugin`을 built-in으로 추가: 오늘의 세션 수·승인/거부/자동승인 비율·가장 자주 승인한 도구·세션별 소요 시간.

- 효과: 플러그인 플랫폼의 첫 "데이터 소비형" 사례 — v2 생태계의 레퍼런스 구현이 된다.

## 4. Horizon 2 — "1대에서 N대 관제로" (v0.16~v1.0, 3~9개월)

병렬 에이전트 운용을 1급 시나리오로 승격하는 단계. v1.0의 정체성을 결정한다.

### H2-1. Fleet 보드

확장 노치(또는 분리 창)를 세션 카드 그리드로: 워크스페이스·브랜치·상태(작업 중/승인 대기/idle/오류)·경과 시간을 한 화면에. 정렬 기준은 "내 결정이 필요한 순". 서브에이전트는 부모 카드에 중첩.

- 현재 세션 리스트는 단일 컬럼 행 구조라 5개 이상이면 인지 한계. fleet 보드가 이를 대체.
- 원칙 3(1초 인지)의 N세션 버전: 카드 색·정렬만으로 "어디 봐야 하는지"가 보여야 한다.

### H2-2. Git 컨텍스트

세션 카드에 브랜치명, dirty 여부, ahead/behind, (옵션) PR 번호·CI 상태를 표시. `workspaceRoot`가 이미 모든 세션에 있으므로 로컬 git 읽기는 즉시 가능. PR/CI는 `gh` CLI 호출 opt-in.

- 여러 워크트리를 굴릴 때 "이 세션이 어떤 작업이더라"를 해결 — fleet 보드의 식별성을 완성하는 기능.

### H2-3. 승인 정책 프로파일

룰 시스템을 "프로파일" 단위로 묶는다:

- **워크스페이스 프로파일**: 신뢰하는 저장소에는 관대한 룰셋, 새 저장소에는 엄격한 룰셋. (`workspaceRoot` 스코프 룰이 이미 있어 그룹화 UI가 핵심)
- **시간제한 자동 승인 윈도우**: "이 세션, 30분간 safe/low 위험 도구 자동 승인" — 만료 시각을 노치에 카운트다운으로 표시하고 자동 해제. `ToolKnowledge` 위험도 + `session_cache.expiresAt`(스키마에 이미 존재)으로 구현.
- 원칙 2 준수: 무기한·전역 자동 승인은 제공하지 않는다. 모든 완화는 범위(워크스페이스/세션)와 시간이 명시된다.

### H2-4. 외부 알림 채널 (플러그인)

Slack/Discord/일반 webhook으로 "승인 대기 5분 초과", "세션 오류", "긴 작업 완료" 전송. 플러그인 v2의 `networkAccess` 권한 1호 사례로 구현해 권한·감사 설계를 검증한다.

### H2-5. 비용·토큰 추적 (가능한 provider부터)

훅 페이로드에 토큰/모델 정보가 포함되는 provider부터 세션별 토큰·추정 비용을 집계. 인사이트 플러그인에 합산. 페이로드에 없으면 무리해서 transcript 파싱하지 않는다(로컬 우선·정확성 원칙).

### H2-6. Provider SDK화

`HookEventNormalizer`/`ProviderAdapter`의 provider 분기를 선언형 디스크립터(이벤트 매핑·승인 이벤트·응답 템플릿)로 정리해, 신규 CLI 에이전트(예: Aider, OpenCode 류) 추가가 "디스크립터 + 어댑터 테스트" 수준이 되게 한다. 커뮤니티 기여를 받는 첫 관문.

## 5. Horizon 3 — "플랫폼" (v1.0 이후, 9개월~)

### H3-1. 원격 승인 (컴패니언)

자리를 비운 사이 승인 요청을 휴대폰에서 처리. 형태 후보:

| 형태 | 장점 | 단점 |
|---|---|---|
| iOS 컴패니언 앱 + 로컬 네트워크(Bonjour) | 같은 Wi-Fi에서 단순, 서버 불필요 | 외부망 불가 |
| iOS 앱 + 자체 relay (E2E 암호화) | 어디서나 | 서버 운영 부담, 보안 책임 |
| Tailscale 등 사용자 VPN 전제 + 웹 UI | 서버 불필요, 파워유저 친화 | 진입 장벽 |

**권고**: 1단계는 로컬 네트워크 + 사용자 VPN 조합(서버 무운영)으로 시작.

**절대 선결 조건**: 기술 로드맵 S1~S5 완료(루프백 바인딩, 토큰 필수화, 서명 릴리스). 원격 표면을 여는 것은 현재 IPC 보안 수준에서는 금지. 승인 채널에는 별도 페어링(QR + 키 교환)과 결정 서명을 설계한다.

### H3-2. 플러그인 v2 + 커뮤니티 생태계

설계 문서의 v2 로드맵 실행: declarative preset → 외부 plugin runtime(worker 프로세스 격리) → 서명 배포. 여기에 **에셋 생태계**를 얹는다:

- 버디(픽셀 캐릭터) 팩, OpenPeon 사운드 팩, 플러그인을 묶는 공통 패키지 포맷
- 앱 내 갤러리(설치/삭제), 서명 검증
- OpenPeon 팩 로더와 CESP 검증기가 이미 "외부 콘텐츠를 안전하게 로드"하는 선례 — 같은 패턴을 일반화

이 단계의 성공 지표는 "외부 기여자가 코어 PR 없이 만든 확장이 존재하는가"다.

### H3-3. 팀·조직 기능 (가볍게)

- 룰셋 export/import(JSON) → 저장소에 커밋 가능한 `.devisland/policy.json` (프로젝트 단위 정책 공유)
- 조직 관리 콘솔 같은 무거운 방향은 가지 않는다 — 파일 기반 공유까지가 비전 적합 범위.

## 6. 안티골 — 하지 않을 것

방향을 지키는 것은 기능 목록만큼 중요하다.

| 안티골 | 이유 |
|---|---|
| 터미널/에디터 대체 (내장 터미널, 코드 뷰어 확장) | 원칙 1 위반. 포커스 복원이 정체성이지, 작업 공간 흡수가 아니다 |
| 에이전트 자체 내장 (DevIsland가 LLM 호출) | 관제탑이 비행기를 조종하기 시작하면 중립성(승인 게이트 신뢰)이 무너진다 |
| 에이전트 오케스트레이터화 (자동 작업 분배·재시도) | 같은 이유. 세션 시작 보조(Quick Launch)까지가 경계 |
| 클라우드 계정 강제·텔레메트리 기본 켬 | 원칙 4 위반 |
| 무기한 전역 자동 승인 스위치 | 원칙 2 위반. 모든 완화는 범위·시간 한정 |

## 7. 배포·커뮤니티 성장 (기능 외 병행 과제)

오픈소스 제품으로서 기능만큼 중요한 트랙:

- **Homebrew cask 배포** (`brew install --cask devisland`) — 서명·공증(기술 로드맵 S5) 완료가 선결
- **영문 README + 데모 GIF** — 현재 README는 한국어 단일, showcase 이미지는 깨져 있음(검토 보고서 D4). 국제 사용자 유입의 병목
- **provider별 5분 설치 가이드** 및 트러블슈팅 문서 (H1-2 진단 뷰와 연동)
- 플러그인 v2 시점에 **확장 개발자 문서** 공개
